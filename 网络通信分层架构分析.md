# secs4java8 网络通信分层架构分析

本文档对 `com.shimizukenta.secs` 包中的网络通信架构进行分层分析，涵盖应用层、传输层、物理链路层，以及层与层之间的衔接机制。

---

## 一、整体架构概览

secs4java8 库实现了半导体制造行业中 SECS/HSMS 通信协议栈。整体采用分层设计，支持两种物理传输路径：

```
┌─────────────────────────────────────────────────────────────────┐
│                        应用层 (Application)                      │
│   GEM (SEMI-E30)  │  SML (SECS Message Language)  │  Secs2     │
│   gem/            │  sml/                          │  secs2/    │
├─────────────────────────────────────────────────────────────────┤
│                        传输层 (Transport)                        │
│   HSMS-SS (SEMI-E37.1)  │  HSMS-GS (SEMI-E37.4)  │  SECS-I    │
│   hsmsss/               │  hsmsgs/               │  secs1/    │
├─────────────────────────────────────────────────────────────────┤
│                     物理链路层 (Physical/DataLink)                │
│   TCP/IP (AsynchronousSocketChannel)  │  Serial (RS-232)        │
│   secs1ontcpip/ (SECS-I over TCP/IP)  │  外部串口适配            │
├─────────────────────────────────────────────────────────────────┤
│                        网络层 (Network)                          │
│   Java NIO AsynchronousSocketChannel / AsynchronousServerSocket │
└─────────────────────────────────────────────────────────────────┘
```

### 核心包对应关系

| 层次 | 包名 | 对应协议 | 职责 |
|------|------|---------|------|
| 应用层 | `gem/` | SEMI-E30 (GEM) | 设备管理模型、业务命令 |
| 应用层 | `secs2/` | SEMI-E5 (SECS-II) | 数据编码/解码 |
| 应用层 | `sml/` | SML | 消息文本解析 |
| 传输层 | `hsmsss/` | SEMI-E37.1 (HSMS-SS) | 单会话TCP通信 |
| 传输层 | `hsmsgs/` | SEMI-E37.4 (HSMS-GS) | 多会话TCP通信 |
| 传输层 | `secs1/` | SEMI-E4 (SECS-I) | 串行块传输协议 |
| 传输层 | `hsms/` | HSMS 公共 | 消息帧格式、会话管理 |
| 物理链路层 | `secs1ontcpip/` | SECS-I on TCP/IP | 串口协议适配到TCP |
| 公共基础 | `impl/` | - | 通信器基类、观察者模式 |
| 公共接口 | 根包 | - | `SecsCommunicator`、`SecsMessage` 等 |

## 二、物理链路层（Physical / Data Link Layer）

物理链路层负责实际的字节流收发，是整个协议栈的最底层。库中支持两种物理链路：

### 2.1 TCP/IP 链路（主要方式）

使用 Java NIO 的 `AsynchronousSocketChannel` 实现异步 TCP 通信。

**关键类：**
- `AbstractHsmsAsynchronousSocketChannelFacade`（`hsms/impl/`）—— HSMS 协议的 TCP 信道封装
- `AbstractSecs1OnTcpIpCommunicator`（`secs1ontcpip/impl/`）—— SECS-I over TCP/IP 的信道实现
- `AbstractSecs1OnTcpIpReceiverCommunicator`（`secs1ontcpip/impl/`）—— SECS-I over TCP/IP 的接收端（Passive）实现

**TCP 发送核心代码（HSMS）：**

```java
// AbstractHsmsAsynchronousSocketChannelFacade.java
// 发送字节缓冲区，处理半包问题
private void sendByteBuffer(ByteBuffer buffer)
        throws HsmsException, ExecutionException, InterruptedException {
    
    while (buffer.hasRemaining()) {
        final Future<Integer> future = this.channel.write(buffer);
        int w = future.get().intValue();
        if (w <= 0) {
            throw new HsmsDetectTerminateException();
        }
    }
    this.linktestReset();
}
```

**TCP 接收核心代码（SECS-I on TCP/IP）：**

```java
// AbstractSecs1OnTcpIpCommunicator.java
// 从 TCP 信道读取字节，放入 SECS-I 电路层的队列
private void reading(AsynchronousSocketChannel channel) throws Exception {
    final ByteBuffer buffer = ByteBuffer.allocate(1024);
    for ( ;; ) {
        ((Buffer)buffer).clear();
        Future<Integer> f = channel.read(buffer);
        int r = f.get().intValue();
        if (r < 0) { break; }
        ((Buffer)buffer).flip();
        byte[] bs = new byte[buffer.remaining()];
        buffer.get(bs);
        putBytes(bs);  // 将原始字节注入到 SECS-I 电路层
    }
}
```

### 2.2 串行链路（Serial / RS-232）

SECS-I（SEMI-E4）原生设计为串行通信协议。库中通过 `AbstractSecs1Communicator` 的抽象方法 `sendBytes()` 提供串行接口，具体实现由外部适配器完成（如 `raspi-python/TcpIpSerialConverter` 示例）。

### 2.3 物理链路层的设计特点

1. **异步非阻塞 I/O**：使用 `AsynchronousSocketChannel`，通过 `Future` 和 `CompletionHandler` 实现异步读写
2. **半包/粘包处理**：
   - HSMS：通过 4 字节长度前缀帧协议解决，先读 4 字节长度，再读完整消息
   - SECS-I over TCP/IP：通过 `putBytes()` 将原始字节注入到 SECS-I 电路层的阻塞队列中，由电路层按 ENQ/EOT/ACK/NAK 协议帧边界解析
3. **连接管理**：Active 模式主动连接，Passive 模式监听接受连接，支持自动重连/重绑定

## 三、传输层（Transport Layer）

传输层在物理链路之上提供可靠的消息传输服务，包括 HSMS（TCP/IP 直接传输）和 SECS-I（串行块传输）两种协议。

### 3.1 HSMS 传输层（SEMI-E37）

HSMS 是基于 TCP/IP 的高速消息服务，分为 SS（单会话）和 GS（多会话）两种模式。

#### 3.1.1 HSMS 消息帧格式

```
┌──────────────┬──────────────────────┬──────────────────┐
│ 4字节长度     │ 10字节消息头          │ SECS-II 消息体    │
│ (大端序)      │ (Session/Stream/...) │ (可变长度)        │
└──────────────┴──────────────────────┴──────────────────┘
```

**帧格式解析核心代码：**

```java
// AbstractHsmsAsynchronousSocketChannelFacade.java - taskReceiveMessage()
// 1. 先读 4 字节长度
ByteBuffer lengthBuffer = ByteBuffer.allocate(8);
lengthBuffer.put(length4Zero);  // 前4字节填0，凑满8字节读long
this.readingBufferFirst(lengthBuffer);
while (lengthBuffer.hasRemaining()) {
    this.readingBuffer(lengthBuffer);
}
((Buffer)lengthBuffer).flip();
long msgLength = lengthBuffer.getLong();

// 2. 再读 10 字节消息头
ByteBuffer headerBuffer = ByteBuffer.allocate(10);
while (headerBuffer.hasRemaining()) {
    this.readingBuffer(headerBuffer);
}

// 3. 最后读消息体（可能分多个 buffer）
for (long rem = msgLength - 10L; rem > 0L; ) {
    long bodySize = this.prototypeDefaultReceiveBodySize(); // 1024
    int size = (int)(rem > bodySize ? bodySize : rem);
    ByteBuffer bf = ByteBuffer.allocate(size);
    while (bf.hasRemaining()) {
        rem -= (long)(this.readingBuffer(bf));
    }
    bodyBuffers.add(bf);
}
```

#### 3.1.5 HSMS 事务管理（Transaction）

HSMS 使用 System Bytes（消息头第 6-9 字节）进行事务匹配，实现请求-响应关联：

```java
// AbstractHsmsAsynchronousSocketChannelFacade.java
private final Map<Integer, SendAndReceiveMsgPack> transactionMap = new HashMap<>();

// 发送时注册事务
public Optional<HsmsMessage> send(HsmsMessage msg) {
    final Integer key = getSystemBytesKey(msg);  // 从消息头提取 system bytes
    final SendAndReceiveMsgPack pack = new SendAndReceiveMsgPack(msg);
    
    if (timeout != null) {
        synchronized (this.transactionMap) {
            this.transactionMap.put(key, pack);  // 注册等待响应
        }
    }
    sendMsgQueue.put(pack);  // 放入发送队列
    // 等待发送完成和响应...
}

// 接收时匹配事务
private AbstractHsmsMessage putMessageToTransaction(AbstractHsmsMessage msg) {
    final Integer key = getSystemBytesKey(msg);
    synchronized (this.transactionMap) {
        SendAndReceiveMsgPack pack = this.transactionMap.get(key);
        if (pack == null) {
            return msg;  // 非事务消息，作为 Primary 消息投递
        } else {
            pack.recvMsg = msg;  // 匹配到等待的响应
            this.transactionMap.notifyAll();
            return null;
        }
    }
}
```

#### 3.1.6 HSMS 超时机制

| 超时 | 含义 | 使用场景 |
|------|------|---------|
| T3 | 发送数据消息后等待响应的超时 | `send()` 中 wbit=1 时 |
| T5 | 连接断开后重试等待时间 | Active/Passive 重连间隔 |
| T6 | 发送控制消息后等待响应的超时 | SELECT/LINKTEST 等 |
| T7 | 等待初始消息的超时 | Passive 等待 SELECT.REQ |
| T8 | 接收消息字节间超时 | 读取消息体时的间隙超时 |

### 3.2 SECS-I 传输层（SEMI-E4）

SECS-I 是面向串行通信的块传输协议，将消息拆分为固定大小的块（最大 257 字节），通过 ENQ/ACK 握手实现可靠传输。

#### 3.2.1 SECS-I 块格式

```
┌────────┬──────────┬──────────┬──────────┬──────────┬──────────┬────────┐
│ Length │ Header1  │ Header2  │ Header3  │ Header4  │ ...Body  │ CheckSum│
│ (1byte)│ (10 bytes header)             │          │ (max 244)│ (2byte) │
└────────┴──────────┴──────────┴──────────┴──────────┴──────────┴────────┘
     0        1         2         3         4        5..N       N+1..N+2
```

**块结构解析：**

```java
// AbstractSecs1MessageBlock.java
public AbstractSecs1MessageBlock(byte[] bs) {
    // 块总长度 13~257 字节
    if (bs.length >= 13 && bs.length <= 257) {
        this.length = (int)(bs[0]) & 0x000000FF;  // 长度字节
        if (this.length >= 10 && this.length <= 254) {
            if ((this.length + 3) == bs.length) {
                // 校验和验证
                int v = ((int)(bs[i + 1]) << 8) & 0x0000FF00;
                v |= (int)(bs[i + 2]) & 0x000000FF;
                for (; i > 0; --i) {
                    v -= (int)(bs[i]) & 0x000000FF;
                }
                this.valid = (v == 0);
            }
        }
    }
    if (this.valid) {
        this.deviceId = (((int)(bs[1]) << 8) & 0x00007F00) | ((int)(bs[2]) & 0xFF);
        this.ebit = ((int)(bs[5]) & 0x80) == 0x80;     // 结束位
        this.blockNumber = (((int)(bs[5]) << 8) & 0x7F00) | ((int)(bs[6]) & 0xFF);
    }
}
```

#### 3.2.2 SECS-I 电路层（Circuit Facade）

电路层是 SECS-I 的核心，负责块级别的发送/接收/重试：

```java
// AbstractSecs1CircuitFacade.java
// 控制字符定义
private static final byte ENQ = (byte)0x05;  // 请求发送
private static final byte EOT = (byte)0x04;  // 发送结束
private static final byte ACK = (byte)0x06;  // 确认
private static final byte NAK = (byte)0x15;  // 否认

// 发送流程（带重试）
private void enter() throws InterruptedException {
    ByteOrSecs1Message v = this.queue.takeByteOrSecs1Message();
    
    if (v.messagePack != null) {
        // 有消息要发送
        for (int retry = 0; retry <= config.retry().intValue(); ) {
            this.sendByte(ENQ);                    // 1. 发送 ENQ
            Byte b = this.queue.pollByte(T2);       // 2. 等待 EOT
            if (b.byteValue() == EOT) {
                if (this.sending(pack.present())) { // 3. 发送块，等 ACK
                    if (pack.ebit()) {
                        sendMgr.putSended(pack.message); // 最后一块，完成
                        return;
                    } else {
                        pack.next();                // 下一块
                        break;
                    }
                }
            }
            retry++;  // 重试
        }
        sendMgr.putException(pack.message, new Secs1RetryOverException());
    }
}

// 接收流程
private void receiving() throws Secs1Exception, InterruptedException {
    this.sendByte(EOT);                      // 1. 回复 EOT
    int len = pollLengthByte(T2);            // 2. 读长度字节
    byte[] bs = pollBlockBytes(len + 3, T1); // 3. 读完整块
    AbstractSecs1MessageBlock block = new AbstractSecs1MessageBlock(bs);
    
    if (block.checkSum()) {
        this.sendByte(ACK);                  // 4. 校验通过，发 ACK
    } else {
        this.sendByte(NAK);                  // 4. 校验失败，发 NAK
        return;
    }
    
    // 5. 块组装：按 system bytes 和 block number 拼装
    if (block.ebit()) {
        AbstractSecs1Message s1msg = Secs1MessageBuilder.buildFromBlocks(cacheBlocks);
        Secs1Message m = this.transMgr.put(s1msg);  // 事务匹配
        if (m != null) {
            secs1MessageReceiveObserver().putSecs1Message(m);  // 投递给上层
        }
    } else {
        // 等待下一块的 ENQ
        Byte b = this.queue.pollByte(T4);
        if (b.byteValue() == ENQ) {
            this.receiving();  // 递归接收下一块
        }
    }
}
```

#### 3.2.3 SECS-I 超时机制

| 超时 | 含义 |
|------|------|
| T1 | 接收块内字节间超时（等待后续字节） |
| T2 | 等待控制字符（ACK/NAK/EOT/ENQ）超时 |
| T3 | 发送带 WBIT 的消息后等待响应超时 |
| T4 | 多块消息中，等待下一块 ENQ 的超时 |

### 5.3 消息发送链路（自上而下）

以 HSMS-SS 发送 `S1F13` 为例，完整调用链：

```
1. [应用层] Gem.s1f13()
   │  comm.send(1, 13, true, secs2)
   ▼
2. [公共层] SecsCommunicator.send(strm, func, wbit, secs2)
   │  → SecsMessageSendableImpl 默认方法
   ▼
3. [传输层] AbstractHsmsSsCommunicator.send(strm, func, wbit, secs2)
   │  → session.send(strm, func, wbit, secs2)
   ▼
4. [传输层] AbstractHsmsSsSession.send(strm, func, wbit, secs2)
   │  → msgBuilder.buildDataMessage(this, strm, func, wbit, secs2)
   │  → 构建 HsmsMessage（10字节头 + SECS-II body）
   │  → this.send(hsmsMessage)
   ▼
5. [传输层] AbstractHsmsSession.send(HsmsMessage msg)
   │  → asyncChannel.send(msg)
   ▼
6. [物理链路层] AbstractHsmsAsynchronousSocketChannelFacade.send(HsmsMessage msg)
   │  → sendMsgQueue.put(pack)  // 放入发送队列
   │  → taskSendMessage() 线程消费队列
   │    → 构建 ByteBuffer: [4字节长度][10字节头][SECS-II body]
   │    → sendByteBuffer(buffer)
   ▼
7. [网络层] AsynchronousSocketChannel.write(buffer)
   │  → TCP 发送
   ▼
   对端接收 ← 逆向解析
```

### 5.4 消息接收链路（自下而上）

```
1. [网络层] AsynchronousSocketChannel.read(buffer)
   │  → TCP 接收字节
   ▼
2. [物理链路层] AbstractHsmsAsynchronousSocketChannelFacade.taskReceiveMessage()
   │  → 读 4 字节长度 → 读 10 字节头 → 读 body
   │  → AbstractHsmsMessageBuilder.buildFromBytes(header, bodyList)
   │  → 构建 AbstractHsmsMessage
   │  → putMessageToTransaction(msg)
   │    ├── 匹配到等待的事务 → 唤醒 send() 的等待线程
   │    └── 未匹配 → primaryMsgQueue.put(msg)  // 作为 Primary 消息
   ▼
3. [传输层] AbstractHsmsSsPassiveCommunicator.mainTask() 
   │  → asyncChannel.takePrimaryHsmsMessage()  // 阻塞等待
   │  → 根据 messageType 分发：
   │    ├── DATA → session.hsmsMessageReceiveObserver().putHsmsMessage(msg)
   │    ├── LINKTEST_REQ → 回复 LINKTEST_RSP
   │    └── SEPARATE_REQ → return (退出)
   ▼
4. [传输层] AbstractHsmsMessageReceiveObserverFacade
   │  → 转换为 SecsMessage
   │  → 通知所有 SecsMessageReceiveListener
   ▼
5. [应用层] 用户注册的 SecsMessageReceiveListener
   │  → secsMessageReceived(msg)
   │  → msg.getStream(), msg.getFunction(), msg.secs2()
   ▼
6. [应用层] Gem 处理或用户代码处理
```

### 5.7 会话（Session）与信道（Channel）的分离设计

HSMS 架构中，Session 和 Channel 是分离的：

```
┌─────────────────────────────────────────┐
│           AbstractHsmsSsCommunicator     │  ← 通信器（对外接口）
│  ┌─────────────────────────────────┐    │
│  │      AbstractHsmsSsSession       │    │  ← 会话（逻辑连接）
│  │  - sessionId, deviceId           │    │
│  │  - channelProp (ObjectProperty)  │    │  ← 信道引用（可动态绑定）
│  │  - hsmsMessageReceiveObserver    │    │
│  │  - hsmsCommunicateStateObserver  │    │
│  └──────────┬──────────────────────┘    │
│             │ setChannel() / unsetChannel()
│             ▼                            │
│  ┌─────────────────────────────────┐    │
│  │ HsmsSsAsynchronousSocketChannel │    │  ← 信道（物理TCP连接）
│  │  - AsynchronousSocketChannel    │    │
│  │  - taskSendMessage()            │    │
│  │  - taskReceiveMessage()         │    │
│  │  - taskLinktest()               │    │
│  │  - transactionMap               │    │
│  └─────────────────────────────────┘    │
└─────────────────────────────────────────┘
```

**关键衔接代码：**

```java
// AbstractHsmsSession.java - 信道绑定
private final ObjectProperty<AbstractHsmsAsynchronousSocketChannelFacade> channelProp;

public boolean setChannel(AbstractHsmsAsynchronousSocketChannelFacade channel) {
    synchronized (this.channelProp) {
        if (this.channelProp.isNull()) {
            this.channelProp.set(channel);
            // 触发状态变更：NOT_CONNECTED → NOT_SELECTED
            return true;
        }
        return false;
    }
}

// 发送时通过信道
public Optional<HsmsMessage> send(HsmsMessage msg) {
    final AbstractHsmsAsynchronousSocketChannelFacade asyncChannel = this.getChannel();
    if (asyncChannel == null) {
        throw new HsmsNotConnectedException();
    } else {
        return asyncChannel.send(msg);
    }
}
```

这种设计使得 HSMS-GS（多会话）可以在同一个 TCP 连接上绑定多个 Session：

```java
// AbstractHsmsGsCommunicator.java
// 多个 Session 共享同一个 Channel
for (AbstractHsmsGsSession session : selectedSessions) {
    session.setChannel(asyncChannel);  // 同一 channel 绑定到多个 session
}
```

## 六、SECS-I 与 HSMS 的架构对比

| 特性 | HSMS (SEMI-E37) | SECS-I (SEMI-E4) |
|------|-----------------|-------------------|
| 物理介质 | TCP/IP | 串行（RS-232）或 TCP/IP 适配 |
| 消息帧 | 4字节长度 + 10字节头 + Body | 块（最大257字节），ENQ/ACK 握手 |
| 连接管理 | SELECT/SEPARATE 控制消息 | 无连接概念（始终在线） |
| 会话支持 | SS: 单会话 / GS: 多会话 | 单设备（通过 Device ID 区分） |
| 事务匹配 | System Bytes (头第6-9字节) | System Bytes (块头第7-10字节) |
| 链路检测 | LINKTEST 控制消息 | 无（依赖物理链路） |
| 最大消息长度 | 4GB (32位长度字段) | 约 62KB (254字节 × 247块) |
| 核心类 | `AbstractHsmsAsynchronousSocketChannelFacade` | `AbstractSecs1CircuitFacade` |

## 七、关键设计模式总结

### 7.1 模板方法模式

`AbstractBaseCommunicator` 定义了 open/close 骨架，子类扩展具体通信逻辑：

```java
public abstract class AbstractBaseCommunicator implements OpenAndCloseable {
    public void open() throws IOException { /* 状态检查 */ }
    public void close() throws IOException { /* 线程池关闭 */ }
}
```

### 7.2 外观模式（Facade）

`HsmsSsAsynchronousSocketChannelFacade` 封装了复杂的 NIO 异步信道操作，向上层提供简洁的 send/receive/linktest 接口。

### 7.3 观察者模式

各层通过 `Observable` + `Listener` 解耦：
- 消息接收：`SecsMessageReceiveObservable`
- 状态变更：`SecsCommunicateStateDetectable`
- 穿透日志：`SecsMessagePassThroughObservable`

### 7.4 工厂方法模式

`HsmsSsCommunicator.newInstance(config)` 根据 Active/Passive 模式创建不同实现：

```java
public static HsmsSsCommunicator newInstance(HsmsSsCommunicatorConfig config) {
    switch (config.connectionMode().get()) {
    case PASSIVE: return new AbstractHsmsSsPassiveCommunicator(config) {};
    case ACTIVE:  return new AbstractHsmsSsActiveCommunicator(config) {};
    }
}
```

### 7.5 队列驱动的事件循环

传输层使用 `BlockingQueue` 实现异步事件循环：
- 发送队列：`sendMsgQueue`（HSMS）、`ByteAndSecs1MessageQueue`（SECS-I）
- 接收队列：`primaryMsgQueue`（HSMS）
- 字节队列：`BlockingQueue<Byte>`（SECS-I 电路层）

## 九、总结

secs4java8 的分层架构具有以下特点：

1. **清晰的分层边界**：物理链路层（TCP/Serial）→ 传输层（HSMS/SECS-I 协议）→ 应用层（GEM/SECS-II），每层职责明确

2. **灵活的适配能力**：通过 `SecsCommunicator` 统一接口，支持 HSMS-SS、HSMS-GS、SECS-I on TCP/IP 三种通信模式，上层应用代码无需修改

3. **异步非阻塞设计**：全栈基于 Java NIO `AsynchronousSocketChannel`，使用线程池 + 队列 + Future 实现高并发

4. **观察者模式解耦**：消息接收、状态变更、日志记录均通过观察者模式通知，层间依赖最小化

5. **事务匹配机制**：HSMS 和 SECS-I 都使用 System Bytes 进行事务关联，支持 WBIT 请求-响应同步等待

6. **健壮的错误处理**：完善的超时机制（T1-T8）、重试机制（SECS-I）、链路检测（HSMS LINKTEST）、异常分类体系
